## Актуальність та проблематика

Пошук незадоволеного ринкового попиту у 2026 році спирається на неструктуровані публічні дані:
обговорення на технічних форумах, питання на Q&A-платформах, звернення в issue-трекерах і статистику
звернень до довідкових ресурсів. Обсяг таких даних для однієї тематичної ніші становить десятки тисяч
документів на місяць, а повторювані скарги розпорошено між джерелами з різними форматами, лімітами
доступу та ліцензіями.

Наявні інструменти аналізу трендів і соціальних згадок формують агреговані показники популярності або
текстові AI-звіти, але не розкривають, як саме обчислено рейтинг ніші, на яких документах він
ґрунтується та наскільки він стабільний до зміни вибірки. Рекомендація без відтворюваної методики не
може бути перевірена, повторена чи оскаржена.

Інженерна складність задачі полягає в поєднанні чотирьох аспектів:

1. Ідемпотентний збір даних із зовнішніх API з дотриманням лімітів запитів, повторними спробами та
   ізоляцією збоїв окремих джерел.
2. Обробка текстового потоку: нормалізація, дедуплікація, псевдонімізація авторів, виявлення скарг і
   тематична кластеризація.
3. Відтворюване багатокритеріальне ранжування з кількісною оцінкою невизначеності.
4. Експлуатаційні властивості: автентифікація та RBAC, rate limiting, кешування, спостережуваність,
   автоматизований контроль якості та безпеки в CI/CD.

## Сформована ідея продукту

DemandLens — вебплатформа на основі модульного моноліту з асинхронним конвеєром обробки даних.
Система збирає публікації з відкритих безкоштовних API, виявляє повторювані скарги та проблеми,
групує потреби за темами, порівнює конкурентів і ранжує ніші за прозорими критеріями. Кожна
рекомендація містить оцінку, перелік джерел, аргументи «за», ризики, довірчий інтервал і пояснення
внеску кожного критерію в підсумковий рейтинг.

Архітектурний тип: модульний моноліт (Django REST Framework) з виділеними асинхронними обробниками
(Celery + Redis), реляційним сховищем PostgreSQL з репліцією, API Gateway на Nginx і контуром
спостережуваності (OpenTelemetry, Prometheus, Grafana). Ранжування є детермінованим: однаковий знімок
даних і однакова версія моделі оцінювання дають однаковий результат.

## Детальний опис функціоналу (Core Features)

1. **CF-01. Ідемпотентний збір даних.** Отримання публікацій з HN Search API, Stack Exchange API,
   GitHub REST API і Wikimedia Analytics API за ключовими словами проєкту з ключем ідемпотентності,
   rate limiting на рівні джерела, експоненційним backoff і Circuit Breaker.
2. **CF-02. Нормалізація та дедуплікація.** Приведення документів до єдиної схеми, вилучення дублікатів
   за SHA-256-хешем вмісту та косинусною близькістю ембедингів, псевдонімізація ідентифікаторів авторів.
3. **CF-03. Виявлення скарг.** Класифікація фрагментів тексту як скарги з обчисленням інтенсивності
   проблеми `pain_score` у діапазоні [0; 1] (лексичні правила + модель логістичної регресії scikit-learn).
4. **CF-04. Тематична кластеризація потреб.** Групування скарг у кластери потреб (TF-IDF, ембединги,
   HDBSCAN) з формуванням ключових термінів і контролем якості кластеризації (silhouette score).
5. **CF-05. Порівняння конкурентів.** Реєстрація конкурентних продуктів ніші та збір їхніх публічних
   метрик (GitHub stars, відкриті issues, кількість релізів, згадки на Hacker News).
6. **CF-06. Прозоре ранжування ніш.** Обчислення рейтингу за п'ятьма нормалізованими критеріями з
   версіонованими вагами та bootstrap-оцінкою довірчого інтервалу і рівня невизначеності.
7. **CF-07. Пояснення та звіти.** Формування для кожної ніші пояснення: внесок критеріїв, посилання на
   документи-докази, аргументи «за», ризики; експорт звіту у JSON і CSV.

## Обмеження проєкту

- Використовуються лише безкоштовні API, моделі та інструменти; платні сервіси й платні API виключено.
- Збір даних виконується з дотриманням умов використання та лімітів кожного джерела.
- Рейтинг формується відтворюваним алгоритмом, а не генеративною моделлю.
