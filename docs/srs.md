# Специфікація вимог до програмного забезпечення (SRS) — DemandLens

| Атрибут | Значення |
|---|---|
| Стандарт | ISO/IEC/IEEE 29148:2018, розділ 9.5 (структура SRS) |
| Версія | 1.0 (ЛР№5, 25.11.2026) |
| Система | DemandLens — платформа виявлення та оцінювання ринкових можливостей |
| Джерело вимог | Розділ 1, підрозділ 1.5 ([1_analysis.md](1_analysis.md#15-постановка-задачі-та-формування-вимог-модель-to-be)) |
| Пов'язані документи | [2_design.md](2_design.md), [ADR-001](adr/0001-choice-of-technology.md), [DECISIONS.md](../DECISIONS.md) |

Модальні дієслова: «повинна» — обов'язкова вимога; «має» — обов'язкова властивість. Кожна вимога
має неповторюваний ідентифікатор, на який посилаються архітектура, контракти і тести.

## 1. Вступ

### 1.1. Призначення

Документ фіксує контракт вимог до системи DemandLens для проєктування (Розділ 2), реалізації та
інструментальної перевірки (Розділ 3). Адресати: розробник, науковий керівник, викладач.

### 1.2. Межі системи (Scope)

Система автоматизує збір публікацій з відкритих API, виявлення та кластеризацію скарг, порівняння
конкурентів і детерміноване ранжування ринкових ніш із поясненням і довірчим інтервалом. Поза межами
системи: платні джерела даних, скрейпінг вебсторінок, генерування висновків мовними моделями,
мобільні клієнти, мультиорендність (multi-tenancy).

## 2. Контекст системи (System Context)

### 2.1. Зовнішні сутності та інтерфейси

| Зовнішня сутність | Тип | Інтерфейс | Напрям |
|---|---|---|---|
| Аналітик | Користувач (роль ANALYST) | Web App → REST API, HTTPS | Вхідний |
| Адміністратор | Користувач (роль ADMIN) | Web App → REST API, HTTPS | Вхідний |
| HN Search API (Algolia) | Зовнішнє джерело | REST/JSON, HTTPS, без ключа, 10 000 запитів/год на IP | Вихідний |
| Stack Exchange API v2.3 | Зовнішнє джерело | REST/JSON, HTTPS, ключ StackApps, 10 000 запитів/добу | Вихідний |
| GitHub REST API | Зовнішнє джерело | REST/JSON, HTTPS, персональний токен, 5 000 запитів/год | Вихідний |
| Wikimedia Analytics API | Зовнішнє джерело | REST/JSON, HTTPS, обов'язковий User-Agent | Вихідний |

### 2.2. Класи користувачів

| Роль | Права |
|---|---|
| `ANALYST` | Створення і перегляд власних проєктів, запуск збору та оцінювання, перегляд скарг, ніш, пояснень, конкурентів, експорт звітів, перегляд переліку джерел |
| `ADMIN` | Усі права ANALYST щодо будь-якого проєкту в режимі читання; зміна налаштувань джерел; перегляд журналу аудиту |

### 2.3. Обмеження проєктування

- Стек: Python 3.12, Django 5.2 LTS, Django REST Framework 3.17, Celery 5, Redis 8, PostgreSQL 17 з
  pgvector 0.8, Next.js 16 + TypeScript + Tailwind CSS, Docker Compose, Nginx.
- Використовуються лише безкоштовні API та інструменти з ліцензіями, що допускають некомерційне
  використання.
- Архітектурний стиль — модульний моноліт з асинхронними обробниками (DECISIONS.md, D-14;
  [ADR-001](adr/0001-choice-of-technology.md)).

### 2.4. Припущення та залежності

- Ліміти зовнішніх API відповідають документації станом на 25.11.2026; зміна лімітів змінює лише
  конфігурацію джерела (SRS-FUN-24), а не код.
- Цільове середовище — один вузол (4 vCPU, 8 GiB RAM) для Core API і одного Analytics Worker,
  окремі контейнери для PostgreSQL primary і replica.

| <a id="srs-nfr-maint-01"></a>SRS-NFR-MAINT-01 | Супроводжуваність | Покриття тестами pytest ≥ 80 % рядків backend; SonarQube Maintainability Rating A; дублювання коду ≤ 3 %. |
| <a id="srs-nfr-repro-01"></a>SRS-NFR-REPRO-01 | Відтворюваність | Однакові знімок даних, версія моделі оцінювання і seed дають ідентичні рейтинги (розбіжність 0). |

| <a id="srs-nfr-infra-01"></a>SRS-NFR-INFRA-01 | Переносимість | Розгортання через Docker Compose; кожен контейнер має health check; конфігурація і секрети передаються лише через змінні середовища. |

## 6. Глосарій (Glossary)

| Термін | Визначення |
|---|---|
| Скарга (complaint) | Фрагмент публікації, класифікований як опис проблеми користувача, з числовою інтенсивністю `pain_score` ∈ [0; 1] |
| Ніша (niche) | Кластер потреб, що розглядається як ринкова можливість і отримує рейтинг |
| Ідемпотентність | Властивість операції, повторне виконання якої з тим самим ключем не змінює результат і не створює дублікатів |
| Circuit Breaker | Патерн відмовостійкості, що припиняє виклики до зовнішньої залежності після серії помилок і періодично перевіряє її відновлення |
| JWT (JSON Web Token) | Підписаний токен з набором тверджень (claims), що засвідчує автентифікацію і роль користувача |
| Latency p95 | Значення часу відповіді, яке не перевищують 95 % запитів за вимірюваний інтервал |
| Bootstrap-інтервал | Довірчий інтервал, отриманий перцентилями статистики на повторних вибірках із поверненням |
