# Мета роботи

Розгорнути інженерне PKM-середовище та Docs-as-Code контур у Git, проаналізувати еталонні
архітектурно-інфраструктурні напрями спеціальності F2, специфікувати первинний технічний концепт
кваліфікаційного проєкту, провести його AI-асистовану валідацію та підготувати фідбек-петлю з науковим
керівником.

# Завдання 1. Розгортання PKM Workspace та структури Листа завдання

У Notion створено приватну кореневу сторінку-хаб `F2_Diploma_Кока_МС`, що виконує роль окремого
робочого простору кваліфікаційного проєкту. Склад сторінки наведено в таблиці 1.1.

Таблиця 1.1 — Структура PKM Workspace

| Блок | Тип Notion | Вміст |
|---|---|---|
| Паспорт проєкту | Таблиця на сторінці | ПІБ студента; ПІБ наукового керівника — «—» (не призначений); 121/F2 «Інженерія програмного забезпечення»; робоча назва теми; посилання на Git-репозиторій |
| Репозиторій артефактів | База даних | Назва артефакту, тип (розділ пояснювальної записки, наукова стаття, звіт інструментального аудиту, звіт ЛР, специфікація), посилання, ЛР, статус |
| Календарний план — шаблон (ЛР№1) | База даних | Порожня матриця з фіксованими графами |
| Supervisor Feedback | Callout | Статус «очікується» |
| Thesis_Proposal | Підсторінка | Технічна картка ідеї |
| AI Insights (AI Disclosure) | Підсторінка | Протоколи взаємодії з ШІ за кожну ЛР |

Таблиця 1.2 — Фіксовані графи бази «Календарний план»

| Графа | Тип властивості | Значення на етапі ЛР№1 |
|---|---|---|
| № з/п | Number | Порожньо |
| Назва етапу кваліфікаційної роботи | Title | Порожньо |
| Термін виконання етапів проєкту | Date | Порожньо (заповнюється після затвердження теми) |
| Примітка / Статус виконання | Select: To Do / In Progress / Done | Порожньо |

Спільний доступ у режимі Can comment для викладача та наукового керівника налаштовується студентом
вручну після отримання їхніх облікових записів.

# Завдання 4. Запуск контуру Docs-as-Code

Створено публічний репозиторій [github.com/Maks-Koka/F2-diploma-project](https://github.com/Maks-Koka/F2-diploma-project) зі структурою
`/src` (майбутній код) і `/docs` (документація). Файл `docs/proposal.md` містить очищену технічну
картку. Перший коміт виконано за угодою Conventional Commits:
`feat: initialize docs-as-code structure with thesis proposal`. Посилання на репозиторій додано до
Паспорта проєкту в Notion.

# Завдання 5. Верифікація керівником

Блок Supervisor Feedback створено в PKM Workspace. Науковий керівник на дату виконання роботи не
призначений, тому відгук не зафіксовано. Після отримання відгуку передбачено: внесення тексту відгуку в
блок Supervisor Feedback, коригування `docs/proposal.md` і коміт
`fix: адресація зауважень керівника`.

# Висновки

Розгорнуто PKM Workspace із Паспортом проєкту, Репозиторієм артефактів і порожньою матрицею
Календарного плану. Сформовано технічну картку проєкту DemandLens: модульний моноліт з асинхронним
конвеєром обробки даних, сім Core Features і стек технологій, розподілений за вісьмома категоріями.
Проведено AI-аудит відповідності рівню F2: прийнято дев'ять рекомендацій щодо ускладнення архітектури,
дві відхилено з обґрунтуванням. Ініціалізовано Docs-as-Code контур у публічному Git-репозиторії.
Фідбек-петля з науковим керівником очікує призначення керівника.
